# Editorial Writing Guide — Manhã Aumentada

## Thesis structure

O editorial (hot-take) deve centrar-se numa tese comparativa ou contrastiva. O leitor já tem acesso aos fatos no Radar; o editorial existe para dar uma perspectiva que ele não teria sozinho.

**Padrão testado e aprovado com o leitor:**
- Contraste entre a narrativa dominante (Ocidente, SV, OpenAI vs Anthropic) e o que está realmente acontecendo (China, código aberto, entrega)
- Comparação quantitativa: "enquanto X fez Y, Z fez W"
- Tese de incentivos: explicar POR QUE os atores se comportam de forma diferente (não apenas O QUE fizeram)

## Tom e estilo

- Opinativo, não neutro. O editorial não é um resumo de notícias — é um take.
- Frases curtas intercaladas com médias. Ritmo variado.
- Bold apenas na headline. Não usar bold no corpo.
- Máximo de 1 em dash por parágrafo. Preferir ponto final ou vírgula.
- Evitar negativas paralelas ("não é X, é Y"). Preferir afirmações diretas.
- Evitar "regra de três" (listas de três itens como recurso retórico).
- Evitar anúncios retóricos ("a história que ninguém capturou", "o que realmente importa").
- Conclusão específica e provocativa, não genérica ("o futuro é brilhante").
- Zero anglicismos. Especialmente: evitar verbificar termos ingleses ("open-sourcou", "shippou", "deployou"). Usar "disponibilizou em código aberto", "lançou", "implementou".

## Estrutura recomendada

1. **Headline**: tese em 10-15 palavras. Deve conter o contraste central.
2. **Abertura (1 parágrafo)**: contexto + listagem compacta dos fatos. Sem exageros.
3. **Tese (1-2 parágrafos)**: a comparação ou contraste. Por que isso importa.
4. **Fechamento (1 parágrafo)**: punchline. Deixar o leitor com algo para pensar.

## Verificação de fontes

- Preferir fontes oficiais (blog técnico da empresa, comunicado à imprensa, GitHub oficial) a agregadores.
- Verificar a DATA de cada item individualmente. Um roundup/agregador pode listar releases de meses diferentes como se fossem um único evento.
- Se a tese depende de "lançamento simultâneo", verificar se é verdadeiro. Caso contrário, ajustar a tese para "acúmulo estratégico" ou "sequência planejada".
- Documentar as fontes no próprio texto (link para fonte oficial).

## Exemplo de fluxo de correção

1. Agregador (AIToolly) lista 8 releases do Meituan como roundup → parece que foram todos no mesmo dia
2. Verificação no blog oficial (tech.meituan.com) → cada release tem data diferente (abril a junho)
3. Tese ajustada: não é "lançamento simultâneo", é "acúmulo estratégico de Q2"
4. Narrativa mantida: contraste entre cobertura americana e entrega chinesa ainda é válido
