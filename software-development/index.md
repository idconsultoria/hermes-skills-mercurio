# software-development — Produto e processo

Progressive disclosure: skills desta categoria (foco ID Consultoria).

- `backlog-and-sprint` — Gestão de backlog e execução de Sprint.
- `baas-offline-migration` — Migrar SPA que usa Supabase p/ backend próprio offline.
- `bpmn-diagram-renderer` — Renderizar BPMN 2.0 (XML) para SVG/PNG via bpmn-js.
- `dedalo-squad` — Pipeline Dédalo Squad — mapeamento de processos com POPs.
- `dogfood` — Exploratory QA of web apps: find bugs, evidence, reports.
- `hermes-agent-skill-authoring` — Author in-repo SKILL.md files: frontmatter e estrutura.
- `ideation-drilling` — Ideação de produto (Fase 1) — refinar ideias brutas.
- `inspecting-hermes-desktop-dom` — Read the live Hermes desktop DOM/CSS over CDP.
- `internal-python-job-executor` — Executor interno Python p/ pipeline no backend FastAPI.
- `local-postgres-sandbox` — Verify DB behavior via local Postgres sandbox from app dump.
- `motor-nfse-id` — Resume/update o motor NFS-e da ID (living state).
- `node-inspect-debugger` — Debug Node.js via --inspect + Chrome DevTools Protocol.
- `pipeline-educacional` — Pipeline de produto educacional — concepção a entrega.
- `plan` — Write a markdown plan to .hermes/plans/; no execution.
- `postgres-dump-restore` — Seed Postgres de dump; evita falha 'unsupported version'.
- `postgres-sandbox-verification` — Verify features really persist against a throwaway Postgres.
- `process-augmentation-pipeline` — Pipeline da ID: análise de processos e augmentação.
- `python-debugpy` — Debug Python: pdb REPL + debugpy remote (DAP).
- `requesting-code-review` — Pre-commit review: security scan, quality gates, auto-fix.
- `simplify-code` — Parallel 4-agent cleanup of recent code changes.
- `skills-repo-curator` — Gestão do repo de skills — consolidação, MECE, OKF.
- `spike` — Throwaway experiments to validate an idea before build.
- `static-spa-vercel` — Build static SPA prototypes and deploy to Vercel.
- `supabase-to-selfhost` — Use ao abandonar Supabase: backend próprio offline único.
- `systematic-debugging` — 4-phase root cause debugging: understand bugs before fixing.
- `test-driven-development` — TDD: enforce RED-GREEN-REFACTOR, tests before code.
